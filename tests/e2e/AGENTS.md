# AGENTS.md — tests/e2e

Refines the root [`AGENTS.md`](../../AGENTS.md) for this folder and never contradicts it. The root has how to run these tests, and the lock.

- CI uses Playwright's Chromium: on system Chrome, the `source.videoFile` test of `tests/e2e/no-camera.spec.ts` failed in one run on Windows (cause not known), so check a failure there on Playwright's Chromium before calling it a regression.
- Checks read from pixels (`tests/e2e/conformance.spec.ts`) hold only on the Chromium revision the repository's locked Playwright installs, which is CI's (`.github/workflows/ci.yml`). In the worktree being tested, run `npm install` first: without its own `node_modules`, `npx playwright` uses the Playwright of a checkout above it (a worktree under `.claude/worktrees/` finds the main checkout's), or downloads the latest. Check that `npx playwright --version` prints the version in `package-lock.json`, then run `npx playwright install chromium`, and run those checks with `PW_CHROMIUM_PATH` unset.
- **Conformance cases** (#130): a behaviour of the adapters is one entry in `CASES` of the "conformance: SceneHandle" table (`tests/e2e/conformance.spec.ts`): an ordered list of `SceneHandle` calls (`AdapterOp`, `tests/e2e/harness/conformance-harness.ts`), the regions to read, and its rules, which the table checks on both engines.
  - Rules: `drawn` / `empty` per engine (alpha ≥ 250 / ≤ 2), `alpha` per engine (within `SAME` of a `value`), `same` across engines (RGBA within `SAME`, 3/255), `sameAlpha`, `edges` of a row, `bounds` (1e-4 mm). `edges` compares every transition along the row between lit (alpha > 128) and unlit: the same number on both engines, each within ±1 px at 128 px, and something drawn on both. A hole is two transitions, so a filled shape with the same outline fails (the torus knot's rows have 4 to 6).
  - A rule reads the final frame, after the last operation, or with `frame: '<name>'` the frame a `{ op: 'render', capture: '<name>' }` read back, so a case checks the state it passes through as well as the one it ends in (the group hidden before it is shown again, alpha 0.5 before 1). The table refuses, per frame read, one with no `drawn`, `edges` or `bounds` rule, and an `empty` without a `drawn` in the same frame, so a blank frame cannot pass; and a rule on a frame no `render` captures. The table has no `look` rule yet: add one, with the report's clipping rule (channels in 30..225), when a case needs a residual the report (`docs/proposals/scene-nodes-equivalence.md`) measured, and use `LOOK` (8/255) only there. The tolerances hold on Chromium revision 1248.
  - The table runs the adapters as the studio does: Babylon.js without exact sRGB (`onBoth(…, false)`).
  - A new adapter method is one more `AdapterOp` kind and one branch of the harness's switch; its spec goes through as it is (JSON only: it crosses `page.evaluate`).
  - A difference the adapters have today is `known: { issue, why, rules, pinned }`: its rules become a `test.fail` test titled with the issue, and a passing test pins what each engine renders. The fix moves `known.rules` into `rules` and removes `known`, which drops the pinned test. The `test.fail` cases written by #129 keep their titles, which #144 and #145 cite.
  - See a new case fail once before trusting it (skip its operation in the harness, or a wrong expected value), then run it with `npm run test:e2e -- tests/e2e/conformance.spec.ts -g "SceneHandle"`.
  - What needs no WebGL (geometry data, bounds, transforms through the real adapters with a fake renderer and Babylon's `NullEngine`) is a Node case in `tests/unit/conformance/`; each such file declares its own `vi.mock` of the renderers, which is hoisted within its file only.
- `PW_NO_LOCK=1` makes `npm run test:e2e` skip the lock as well.
- Each checkout serves its build on its own port, derived from its path; `PW_PORT` picks the port, `PW_REUSE_SERVER=1` tests a server already running on it.
- The e2e global setup (`tests/e2e/global-setup.ts`) turns the photo of the printed marker into a Y4M video for Chromium's fake camera (`tests/e2e/fake-camera.ts`), written to `tests/e2e/.cache/`. The marker is visible for 4 s, then hidden for 2 s, in a loop, so the tests see both found and lost. The loop starts when the camera opens, not when the tracker is ready: the first finding can be cut short by any amount, and under load so can a later one, when the marker is found late after the blank. A test that times a finding measures each one, found to lost, and uses the first long enough for its checks (#91).
- Under a full run's load, one screenshot can take seconds: wait for each state in turn with `expect.poll` (found, then lost, then found) rather than sampling a fixed window or a wall-clock bound (#80, #103).
- Headless Chromium has `showSaveFilePicker`, but rejects it at once with an `AbortError`, which the studio reads as a cancel (#118). `openStudio` (`tests/e2e/helpers.ts`) removes the function before the page loads, so exports download; a test that opens the studio itself calls `withoutSaveDialog`, and one that tests the dialog puts its own `showSaveFilePicker` in the page with `addInitScript`.
- `source.image` mounts an `<img>`, not a `<video>`: a selector on the AR view's `video` matches only the camera and video-file sources.
- Wait for the studio's startup load before picking a demo: `openStudio` and `pickDemo` (`tests/e2e/helpers.ts`) wait for `body[data-startup="done"]`; several demos share their node and link counts, so check the graph's name too (#79).
- No fixed bounds that depend on fonts: Linux renders text wider than Windows, so a layout test measures the elements it checks, not constants (#95).
- A failing test proves something only if it failed for the right reason: a build error stops the server, so every test fails (#85, #87); a retrying assertion can pass on stale content (#81); keep a control that fails without the fix (#80).
- To read what a Three.js frame drew, hook `Scene.onBeforeRender` (or wrap the renderer instance's `render`): `WebGLRenderer.render` is assigned per instance, so patching `WebGLRenderer.prototype.render` does nothing.
